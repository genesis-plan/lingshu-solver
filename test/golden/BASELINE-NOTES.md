# 基线漂移留痕

每次因**产品口径变更**（而非 bug）导致的 golden 基线字段更新，必须在此登记。
纪律：先用 `node test/golden/_show_drift.mjs` 逐字段核实，再改白名单，禁止整份重抓。

## 2026-10-05　去掉人为规则 / 剥离安全认证（v1.0.22 开发期）

一次重构引起 16 个用例的字段漂移，分三类。

### ① 认证元数据消失（11 例，纯预期）

`solutions[].certified` 与 `solutions[].method`（`krawczyk_newton` / `miranda` / …）不再出现。

原因：Krawczyk / Miranda / inflate-and-refine / Smale α 四条区间认证链**退出默认路径**，
改为显式 `{certify:true}` 开启。它们回答的是「解在哪个盒里、误差多大」——
即**误差上界**，Agent 决策不需要，而每解要多轮区间算术。

`tier` 仍为 `proven`：判据换成了**回代验证 + Higham 后向误差**（O(1) 求值，零区间开销）。
涉及 g001、g002、g003、g006、g007、g011、g012、g013、g015、g017、g018。

### ② 精度提升（解值变化，但更准）

| 用例 | 指标 | 基线 | 现值 |
|---|---|---|---|
| g005 | 残差 | 5.54e-13 | **1.78e-15** |
| g007 | 残差 | 3.91e-14 | **7.11e-15** |
| g017 | 解值 | 0.6931471805599454 | **完全相同**（= ln2 双精度最优值） |
| g013 | 解值 | 0.01955308479666175 | 0.01955308479666177（差 2 ULP） |

原因：认证层顺带做的**盒内牛顿精化**被拆出来独立保留（`_refineSolutions`）。
「算得更准」是纯计算，与「给误差上界」是两件事，不该一起关掉。
最初直接关掉认证层时 g017 曾退化成 0.6931471805605547（误差 6.1e-13），
就是漏了这一层；拆开后恢复。

### ③ 完备性证据打通（5 例，修复谎报）

`provenCount: 0 → N`、`candidateCount: N → 0`、`completenessProven: false → true`。
涉及 g005、g009、g014、g019、g020。

原因：这些解本来就被算出来了，但旧代码要求「必须先过 Krawczyk 认证」才给 proven，
于是被压成 candidate ⇒ 完备性证据链（线性满秩 / 同伦 / Bézout 击满）拿不到分母
⇒ 对外报「部分解 / 计算资源不足」。这是**向下游谎报缺陷**（明明找全了却说可能还有）。
判据换成回代验证后自然解开。

g013（公积金月供）另有一条同源 P0：`unconverged`（某条搜索路径没走完）
曾被用来否定「另一条路径已证完」，属证据优先级颠倒，2026-10-05 已单独修过。

### 解值未变的确认

g001 / g002 / g003 / g006 / g012 / g015 / g017 / g018 / g019 / g020 的
**解向量逐位相同**，只有认证元数据字段不同。

### g009 的额外一项

`truncated: false → true`：删掉「距原点最近解」流水线后，欠定路径改走 KKT 投影抢救，
被如实标记为「未穷尽解集」。结论（部分解）、解值 `((0,0))`、解数均未变。

## 同伦完备性谎报修正（2 例：g005 / g007，`resultTypeName` 降级）

**现象**：g005、g007 的 `resultTypeName` 从「全部解」退回「部分解」。
解向量、解数、置信度**全部未变** —— 只有对外结论降级。

**为什么这是修正而不是退化**：旧基线的「全部解」依据是完备性证据
`homotopy_all_paths_clean`，而该证据已被**实测证伪**：

- 3 元对称题 `x+y+z−6, xy+yz+zx−11, xyz−6` 的真解是 {1,2,3} 的 **6** 个排列
  （逐个回代残差 0）。
- 逐条打印同伦 27 条路径终点：全部收敛到 t=1、全部落在实轴上，但只覆盖
  **4 个**不同点 (2,3,1) (3,2,1) (1,2,3) (2,1,3) —— `(1,3,2)` 与 `(3,1,2)`
  **从未被任何路径到达**，而旧代码仍自报 `completenessProven = true`。
- 数学原因（不是实现 bug）：该系统 F = (s1, s2, s3) 是**基本对称多项式**，
  根集对 S₃ 封闭，S₃ 作用使路径必然合并（path coalescence）。此时
  gamma trick 的「每个孤立根被至少一条路径经过」**不再由「全部路径干净」推出**，
  路径大量汇合本身就是「有根未被覆盖」的信号。
- 修法：检测「同一互异根被 ≥3 条路径命中且互异根数 ≪ 路径数」即降级
  （见 `src/engine/operators/homotopy.js` 的 `pathCoalesced`）。

**g005 / g007 的独立核验**：

| 用例 | Bézout 上界 | 实解数 | SymPy 核验 | 诚实结论 |
|---|---|---|---|---|
| g005 | 8（2×1×2×2） | 4 | `sp.solve` ⇒ 恰 4 组：{1,4}×{2,3} 的排列 | 部分解（上界非紧，不可判定） |
| g007 | 4 | 2 | 多起点牛顿（与同伦完全不同的算法）得同 2 组，残差 ≤ 1.8e-15 | 部分解（上界非紧，不可判定） |

按 `rootbound-poly.js` 的 R1 推论，`R < B` ⇒ 既不能断言遗漏也不能断言完备 ⇒
「部分解」是唯一诚实的结论。旧基线的「全部解」建立在一条**已证伪的证据**上。

**反向确认（防止「一律降级」）**：3 元对称题现在**仍然是「全部解」** ——
它换用另一条独立且成立的证据：Bézout 上界 `1×2×3 = 6` 被 6 个互异实根击满
（R == B），这条判据在 `rootbound-poly.js` 里由有理数精确算术给出，
不依赖同伦的路径覆盖性。**证据可以换，诚实不能降。**
