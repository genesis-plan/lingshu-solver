## 一、一句话结论

**灵数与 SymPy 的真正差异不是速度，是「是否给出数学判定」。**

- 纯线性题上，灵数比 SymPy 快 **28.3×**（12/12 题全胜），但比 NumPy 慢 1–2 个数量级 —— 这是**设计使然**
  （灵数走完整认证管线，SymPy 只做消元，NumPy 只做 LU）。
- 非线性 / 丢番图题上，灵数的优势碾压式：**二元 177×、三元 3702×（下界）、能力矩阵非线性区 5–15×**。
- **完备性数学判定：灵数 15/15，SymPy 0/15。** SymPy 的 `linsolve` / `solve` 从不返回
  「我是否证明了没漏解」这个字段 —— 它给的是答案，不是判定。

### NumPy 对照（只跑线性 6 题）

NumPy `lstsq` 0.021–0.065ms，比灵数快 1–2 个数量级，`np_rank` 与裁判一致。
但它**只给数值最小二乘解**：无精确有理、无秩相容性判定、无完备性字段、`illcond` 场景直接病态。
**结论：NumPy 是数值工具，灵数是判定工具，不是替代关系。**

## 七、方法论教训（5 条，都踩过）

1. **没有独立裁判就只能比谁快，没法判谁对。** 两侧都可能是错的。
2. **裁判自己也是代码，也会有 bug。** 初版 RREF 漏了主元行归一化（直接拿 `f = M[i][k]` 去减，
   等于假设主元已是 1，消元系数错）⇒ 把相容的 `presolve-heavy6` 判成不相容，
   我据此差点冤枉灵数「谎报有解」。**裁判必须先过手算小例自检门禁，否则「独立第三方」只是换了个地方出错。**
3. **先确认是不是同一道题，再比。** 两侧曾各造各的随机题（Python `random.seed` vs JS 手写 LCG），
   `sparse-rand6` 根本不是同一道题，对测结论全是废的。⇒ 题面外置成 JSON 单一事实来源。
4. **别凭直觉猜修正。** `rank` 换算返工两次：第一次 `+nFixed`（错），第二次「秩不变」（也错）。
   另外「欠定（列数 > 秩）≠ 无解」—— 我曾把 E2 描述写成「秩亏但无解」，直觉依据是
   「6 未知数只有 4 方程 ⇒ 看着像无解」，独立 BigInt RREF 核验 `rank(A)=3 = rank([A|b])`
   ⇒ **相容，3 维仿射簇**。无解判据是 `rank(A) < rank([A|b])`。
5. **断言红了先查用例本身。** 有一回我写了个 ragged 数组 `[[0,0,0],[0,0,0,5]]`（长度 3 和 4），
   内核返 `rank=undefined` 是合理的。改用等长写法后**才抓到真 bug**（infeasible 缺 rank）。

补充：`provenIsComplete=true` + `provenCount=0` 是**合法声明** —— 无解系统本就 0 个解，
「完备」指已严格证明无解（E1 独立核验 `rank 6 < 7` ⇒ 严格无解）。**能力矩阵 15/15 无谎报。**

## 九、给 AI Agent 客群的实话

灵数**不是** SymPy/NumPy 的替代品，是**互补品**：

- 要数值、要吞吐、不要判定 ⇒ 用 NumPy（快 1–2 个数量级）
- 要符号推导、要参数化表达 ⇒ 用 SymPy
- 要「**这个解是不是全部解**」的数学承诺 + 严格 fail-closed + 单次调用出 JSON ⇒ 用灵数
