LingNao — AI number verification API

Your AI (or your app) produces numbers, formulas, logic. LingNao recomputes them independently — no second model in the loop, no confidence scores — and returns one of three verdicts: verified / refuted / unverifiable. Typical latency ≈ 3 ms.

The three verdicts — there is no fourth

VerdictMeaningWhat to do
verifiedRecomputed independently and matches your claimContinue; archive the proof id with your record
refutedRecomputed independently and contradicts itStop; discard the output; fix the source
unverifiable (𝕌)Nothing checkable, or no claim to compare againstRoute to a human; never treated as "passed"

"Probably fine" is not a verdict. Anything the API cannot check, it refuses to grade — it abstains as unverified(𝕌) with a machine-readable reason (abstainedBy), and never invents a pass. Two abstentions carry real engineering meaning: truncated_solution_set (the solver did not finish within your budget) and engine_unsupported_identifier (the equations contain a variable name the solver cannot parse today).

Quickstart — one HTTP call

curl -X POST https://hongchenlingjing.com/verify \
  -H "Content-Type: application/json" \
  -d '{"caseLabel":"invoice total","items":[{"id":"i1","kind":"algebraic",
        "payload":{"equations":["x+y=z","x=80","y=8"],
                   "claimed":{"z":88}}}]}'

# → {"ok":true,"overall":"verified","items":[{"verdict":"verified", "idx":0, ...}]}

Input kinds: algebraic (equations + claimed values as an object), membership, entail, consistency, constraint. English input gets English verdict text; Chinese in, Chinese out. Every response carries a proof id (reportId) you can archive as evidence.

Variable names. Multi-character names work when you declare them in variables (["subtotal","tax","total"]): the solver keeps them whole, no implicit multiplication gets inserted, and the resolved list is echoed in varNames. If you leave variables empty the default convention is single-letter product parsing (xy → x*y); when that default would blow past the 6-variable cap the engine says so and switches to whole-identifier reading, flagging interpretation:"whole_identifier_fallback". Always read varNames back before trusting values.

Five verifiable claim kinds

kindAskExample item
algebraicDo these equations hold at the claimed values?{"equations":["x+2=5"],"claimed":{"x":3}}
membershipIs the claimed value actually one of the certified solutions?{"kind":"membership","payload":{"equations":["x^2=16"],"claimed":{"x":4}}}
entailDoes every certified solution satisfy the boundary? (P ⊨ x ≤ B){"kind":"entail","payload":{"equations":["x^2=16"],"variables":["x"],"op":"<=","bound":{"x":2}}}
consistencyAre ≥2 statements mutually non-exclusive?{"kind":"consistency","payload":{"statements":[{"id":"a","values":{"staff":12}},{"id":"b","values":{"staff":13}}]}}
constraintBoundary / feasibility claim (compactness theorem){"op":"<=","bound":100}

A refuted entail comes back with a counterexample inside evidence. A consistency verdict of refuted is the single highest-frequency error class in LLM output — two statements contradicting each other on shared variables.

Batch audit — depends, budget and composition law

Items can declare depends:[itemId]; the kernel topologically sorts the DAG and refuses (HTTP 422) if it cycles — it never guesses an evaluation order. The overall verdict obeys one composition law Φ:

∃ item refuted        ⇒ overall = refuted
else ∀ item verified  ⇒ overall = verified
else                  ⇒ overall = unverifiable (𝕌)

An item whose dependency is unresolved or refuted is not judged on its own (abstainedBy:"dependency_unresolved" / "dependency_refuted") — a conclusion may not stand on an unproven premise. Every call also consumes a judgement budget (default 200) measured in primitive evaluations; when it runs out the remaining items return abstainedBy:"budget" as 𝕌 rather than being silently judged. Pass "budget": N to raise it.

curl -X POST https://hongchenlingjing.com/verify \
  -H "Content-Type: application/json" \
  -d '{"caseLabel":"robot shift plan","budget":500,"items":[
        {"id":"sol","kind":"membership","payload":{"equations":["x^2=16"],"claimed":{"x":4}}},
        {"id":"bound","kind":"entail","depends":["sol"],
         "payload":{"equations":["x^2=16"],"variables":["x"],"op":"<=","bound":{"x":2}}}]}'

# → overall:"refuted", compositionLaw:"∃ refuted ⇒ refuted", budget:{used:2,exceeded:false}

LangChain (Python)

import json, urllib.request
from langchain_core.tools import tool

@tool
def lingnao_verify(equations: list[str], claimed: dict) -> str:
    """Recompute numeric conclusions independently.
    Returns verified / refuted / unverifiable — use before acting on AI-computed numbers."""
    req = urllib.request.Request(
        "https://hongchenlingjing.com/verify",
        data=json.dumps({"caseLabel": "agent step", "items": [{
            "id": "i1", "kind": "algebraic",
            "payload": {"equations": equations, "claimed": claimed}}]}).encode(),
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=10) as r:
        return r.read().decode()

Refused domains — by design

Medical, mental-health, education & training, investment or financial advice, legal advice → HTTP 422 with compliance: true. A verification service must refuse what it cannot check. In scope: everyday numbers, formulas, algebraic constraints, logic, safety boundaries.
