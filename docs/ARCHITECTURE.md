## 一、产品概览

**一句话定位**：面向个人用户与 AI Agent 的确定性实数方程组求解器——**输出集中每个解都经数学认证保真，绝不静默给出错误结论**。

| 形态 | 入口 | 说明 |
|---|---|---|
| 在线网页 | `https://hongchenlingjing.com/` | 100% 浏览器本地计算，方程不出设备 |
| MCP 端点（远程） | `https://hongchenlingjing.com/mcp` | streamable-http，供 Claude Desktop / Cursor / Cline 等 AI 客户端 |
| MCP（本地 stdio） | `npx lingshu-solver` | 同上，走本地进程，零数据出机 |
| npm 包 | `npm i lingshu-solver` | 内嵌同一求解核心，可编程调用 |

三种形态共用**同一份求解核心**（`index.html` 内的 `<script id="solver-core">`）。

## 二、数学框架

### 2.1 核心思想：区间算术（可靠优先）

- 所有计算基于**区间算术** `[a, b]` 与**一阶仿射算术**：变量取值永远是"一个盒子"而非一个点，运算结果区间是严格包络——区间不含 0 即**严格证明该盒子内无解**。
- 舍入方向受控，浮点误差不会破坏"包络不含 0 ⇒ 无解"这一sound 性质。

### 2.2 收缩算子（Contractors）

盒子在搜索中不断被"收缩"（保留必然含解的部分、剔除必然无解的部分）：

| 算子 | 方法 | 作用 |
|---|---|---|
| `suan27` | HC4-Revise | 前向严格空集证明 + 反向 hull 一致性收缩 |
| `suan28` | 约束反演系统化 | 广义项一致性，fixpoint 循环，扩展逆函数（含幂逆、log10） |
| `suan31` | Box-Consistency (BC3/3B) | 逐变量盒一致性 |
| `suan32` | 成对 2B / 3B-Consistency | 相邻约束对的一致性 |
| `suan33` | Hansen-Sengupta | 区间 Gauss-Seidel，利用雅可比 |
| `suan34` | LP Narrowing | 精确线性松弛 + 单纯形，可严格证明无解 |

### 2.3 解的认证：Krawczyk 不动点构造

- 输出解列表中的每个点都经 **Krawczyk 算子**认证：解存在于误差半径内，**数学保真，可直接采用**。
- 无法认证的候选点降级为 `candidate`（候选）并明确标注，与 `proven`（已证明）严格区分。

### 2.4 全局搜索：区间分支定界

- `suan47` 全局分支定界：递归二分盒子，配合上表收缩算子剪枝，**尽力穷尽**全部解。
- 预算参数：`BUDGET=5e5` 盒、`MAXDEPTH=28`（单维分辨率约 7e-5）、`MINW=1e-4` 提前停。
- **诚实边界（重要）**：对极端病态系统（雅可比高度奇异、解簇极度贴近），预算内仍可能遗漏个别解。此时结果**显式标记 `truncated` / 残余告警，绝不谎称已穷尽**——这不是缺陷，是数值数学的诚实下界（Richardson/Smale 意义上"保证找到全部解"不可判定）。
- 对周期/高频单变量方程（如 `sin(100x)=0`），`suan22` 周期感知自适应扫描补全全部根。

### 2.5 已知限制（如实声明）

- 整数约束（`x∈ℤ/ℕ`）**不做强制执行**：按实数域求解，返回解不保证为整数；结果中带结构化警告 `integer-unenforced`（不静默忽略）。
- 不等式系统支持可行域判定，结论分级为"有限可行解 / 可行域可能非空"。
- 双曲函数与反三角函数未纳入（低频需求，有意不实现）。
- 5–6 变量强非线性系统可能算不完，只输出已认证的部分结果与范围。

## 三、结构框架

### 3.1 系统组成

```
┌────────────────────────────────────────────────┐
│                 求解核心（唯一真源）              │
│   index.html → <script id="solver-core">        │
└──────┬───────────────┬───────────────┬─────────┘
       │               │               │
  solver-core.js  mcp-server.js  http-mcp-server.js
   （vm 加载器）    （stdio 版）    （streamable-http 版）
       │               │               │
   npm 包/网页     本地 MCP 进程    线上 /mcp 端点
```

### 3.2 部署拓扑与数据流

| 组件 | 位置 | 数据行为 |
|---|---|---|
| 网页求解器 | 静态托管 + 浏览器 | **零数据上行**：方程在浏览器内计算，结果只显示在本机 |
| MCP HTTP 服务 | 服务器 :3000（nginx 反代 `/mcp`） | 方程在内存求解后随应答返回；**不落盘方程与结果** |
| 调用日志 | 服务器本地 `calls.log` | 仅元数据（时间/IP/工具/耗时/结果类型），**不含方程内容**，5MB 轮转 |
| 安全层 | nginx | CSP / X-Frame-Options: DENY / nosniff / 限速 429 / 请求体上限 413 |

### 3.3 隐私与安全设计（当前已落实）

- 无账号、无 Cookie、无埋点、无第三方脚本；不支持图片/文件上传。
- 输入门禁（`_complianceGuard`，网页与 MCP 共用）：拒收自然语言文字 + 100KB 体量上限；**数字串（电话/证件号式）不拦截**，按普通数学常量处理。
- 服务端防护：请求体 256KB 上限（413）、每 IP 120 次/分钟（429）、会话 TTL 清理、反馈落盘前自动脱敏。
- 结果可见性：仅请求者本人可见，无任何公开展示/评论/分享功能（不具舆论属性）。

## 五、算法框架

### 5.1 算子注册表

核心内置 **49 个编号算子**（`suan1`–`suan49`，编号非连续），按阶段分组注册：

| 分组 | 职责 |
|---|---|
| `OPS_SETUP / PRE` | 输入归一、D0 初始化、变量预处理 |
| `OPS_SCREEN` | 前向传播矛盾检测、结构恒正/恒负剪枝、快速矛盾检测（秒级证无解） |
| `OPS_ALGEBRA / ALGEBRA2` | 代数消元、有理根定理、多项式分解 |
| `OPS_CONTRACT` | 六大收缩算子（见 2.2） |
| `OPS_NUMERIC` | 多起点牛顿、周期感知扫描（`suan22`） |
| `OPS_POST / OUTPUT` | 解验证、反例剔伪根、结果分类与诚实标注 |
| `OP_BRANCH / INEQ / GEOMETRY` | 全局分支定界（`suan47`）、不等式处理、投影剪枝（`suan35`/`suan36`） |

### 5.2 防失控三道保险

1. **共享根时钟**：整个递归子树共享同一时间起点（硬超时 8 秒级）。
2. **共享预算池**：分支定界子调用不重置盒预算（历史缺陷已修）。
3. **体量护栏**：方程 ≤64 条、变量 ≤6 个、文本 ≤100KB、请求体 ≤256KB。

### 5.3 结果分类与诚实标注

`resultType` 三大类：`1` 空结果（含严格证明无解）、`2` 有限解、`3` 无限解集（含推荐解）；不等式另有"可行域可能非空"分级。程序化调用方可依赖的结构化标志：`certified`、`truncated`、`provenEmpty`、`integer-unenforced`。

## 六、处理流程（端到端）

```
用户输入（网页文本框 / MCP equations 参数）
   │
   ▼
① 预处理 fuzzyFix（核心层，两路径共用）
   Unicode 归一（− · ≠ 上标 √）→ 换行修复 → 隐式乘法 → log2/log10 识别 → 补 =0
   ▼
② 输入门禁 _complianceGuard：自然语言拒收、100KB 上限
   ▼
③ 解析：tokenize → parse → AST；自动识别变量（含希腊字母 θ/α 归一）
   ▼
④ D0 初始化：用户指定域合并默认域 ±1e6；缺失变量回退默认（不崩溃）
   ▼
⑤ 求解管线 _solveImpl（阶段 1 前置拦截 → … → 阶段 7 分支定界/输出）
   屏幕剪枝 → 代数消元 → 区间收缩（六算子迭代）→ Krawczyk 认证 → 全局分支定界
   ▼
⑥ 收尾 _finish：反例剔伪根 → 良定义校验（_filterIllDefined）→ 结果分类与诚实标注
   ▼
⑦ 输出（网页渲染 / MCP JSON 应答）：解列表 + certified/truncated 等标志
```

网页路径与 MCP 路径仅在 ①⑦ 的入口出口不同，②–⑥ 完全一致。
