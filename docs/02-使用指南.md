| 形态 | 入口 | 安装 | 费用 | 数据 |

## 二、网页版

打开链接 → 在输入框写方程（一行一条，或用 `,` 分隔）→ 点求解。

- 支持 `x^2 + y^2 = 25` 这类等式，也支持 `x ∈ [-30,30]` 这类域约束；符号会做归一化（Unicode 减号、上标、希腊字母等）。
- 没有 `=` 的表达式默认按 `= 0` 处理。
- 页面提供 6 个分类示例，点一下就知道它能解什么。
- 计算全部在浏览器内完成，无上传、无 Cookie、无埋点、无第三方脚本。

## 三、AI Agent 接入（MCP）

### 3.1 推荐：本地 stdio（永久免费、离线）

```json
{
  "mcpServers": {
    "lingshu-solver": {
      "command": "npx",
      "args": ["-y", "lingshu-solver"]
    }
  }
}
```

- Claude Desktop / Cursor / Cline / VS Code 等支持 MCP 的客户端通用。
- 也可 `git clone` 后用本地路径：

```json
{ "mcpServers": { "lingshu-solver": { "command": "node", "args": ["<绝对路径>/mcp-server.js"] } } }
```

### 3.2 零安装：远程托管端点

```json
{
  "mcpServers": {
    "lingshu-solver": {
      "type": "http",
      "url": "https://hongchenlingjing.com/mcp"
    }
  }
}
```

- 协议：MCP **Streamable HTTP**（`initialize` → `notifications/initialized` → `tools/call`），SSE 与 JSON 两种应答均可解析。
- 计费与免费路径见 [06 · 商业授权与收费](06-商业授权与收费.md#三托管端点计费)；一句话：**传 `honorPaid: true` 就免费放行**。
- 接入请务必用 `https://`：Bearer 凭证走明文 HTTP 会在公网裸奔。

### 3.3 工具清单

| 形态 | 工具 |
|---|---|
| 本地 stdio（`mcp-server.js`） | `solve`、`give_feedback` |
| 托管 HTTP（`http-mcp-server.js`） | `solve`、`give_feedback`、`pay` |

## 四、工具契约

### 4.1 `solve` —— 求解方程组

**入参**

```json
{
  "equations": ["x^2 + y^2 = 25", "x + y = 7"],
  "variables": ["x", "y"],
  "domain": { "x": [-30, 30], "y": [-30, 30] },
  "honorPaid": true
}
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `equations` | ✅ | 方程字符串数组（**每个方程必须独立成数组元素**，整串塞一个元素会解出 0 解）。支持 `+ - * / ^ sqrt log sin cos tan exp abs`，以及 in-text 域约束 `"x ∈ [-30,30]"`；无 `=` 视为 `= 0` |
| `variables` | ✕ | 变量名数组；不填则按出现顺序自动识别（≤ 6 个） |
| `domain` | ✕ | 显式搜索域；**对快增长函数（exp/sinh）或"有限解·部分"演示建议给定**，否则默认 ±1e6 可能剪枝失效并触发 `truncated` |
| `budget` / `maxDepth` | ✕ | 搜索预算（默认 `BUDGET=5e5` 盒、`MAXDEPTH=28`），病态系统可加大重试 |
| `fastMode` | ✕ | 切到 Fast 残差档（1e-3） |
| `honorPaid` | ✕ | **仅托管端点**：`true` = 声明个人/评估用途，免费放行、不验证、不扣余额 |

**出参（节选）**

```json
{
  "resultType": 2,
  "resultTypeName": "finite",
  "certified": true,
  "truncated": false,
  "precisionDecimals": 6,
  "solutionCount": 2,
  "summary": "找到 2 个实数解（全部经 Krawczyk 区间认证）。",
  "recommended": {
    "values": [3, 4], "tier": "proven", "certified": true,
    "text": "x=3.000000, y=4.000000",
    "internals": { "residual": 0, "certifiedRadius": 0.00001 }
  },
  "solutions": [ { "values": [3, 4], "tier": "proven", "certified": true, "text": "x=3.000000, y=4.000000" } ],
  "warnings": [],
  "diagnostics": { "inputError": null, "solverVersion": "lingshu-solver/1.0.10-auditable" }
}
```

| 字段 | 含义 |
|---|---|
| `resultType` | `1=empty`（**已证明**无实数解）/ `2=finite`（有限解）/ `3=infinite`（无限解集，仅给推荐解） |
| `certified` | 是否全部解都已认证 |
| `truncated` | `true` = 预算内未证明已穷尽（**不等于一定漏解**）；可收窄 `domain` 或提高预算重试 |
| `solutionCount` | 解的数量 |
| `summary` | 中文一句话总览，可直接展示给用户或写日志 |
| `recommended` | 距原点最近的解（范数最小） |
| `solutions[]` | 每个解：`values`（6 位小数）、`tier`、`certified`、`text`（人类可读）、`internals`（残差等细节，机器可整块跳过以省 token） |
| `tier` | `proven`（Krawczyk 认证）/ `candidate`（未证但可能为解）/ `structural`（结构推导） |
| `precisionDecimals` | 恒为 `6`（固定规格） |
| `diagnostics` | 诊断信息；`inputError` 非空表示本次是输入不合法，**此时不计费** |

### 4.2 `give_feedback` —— 反馈

Agent 遇到卡点、认为结果有误、或有建议时主动回报。内容只落本地 `feedback.log`，**不外传**。

```json
{ "name": "give_feedback", "arguments": { "message": "x^2=4 期望 2 解", "context": "批量求解场景" } }
```

### 4.3 `pay` —— 托管端点付款与自助入账

```json
{ "name": "pay", "arguments": { "orderId": "LS-20260923-xxxxxx", "selfReportPaid": true } }
```

- 付款完成后调用，`selfReportPaid: true` 表示"我已付款" ⇒ **立即入账、立即放行**，无需等待任何人工审核。
- 只传 `orderId` 不构成付款声明（返回 `self_report_required`，防误入账）。
- 详情与合规口径见 [06 · 商业授权与收费](06-商业授权与收费.md)。

### 4.4 错误

| `error.type` | 触发 | 处理 |
|---|---|---|
| `invalid_input` | 方程不是非空字符串数组 / 单条非字符串 / 方程数 > 64 / 文本 > 100KB / 变量 > 6 / 方程数 < 变量数 | 按返回的提示修正后重试 |
| `internal_error` | 内部异常 | 结构化返回，**绝不泄露内部堆栈** |
| `unknown_tool` | 调用了不存在的工具 | 检查工具名 |

> MCP 约定：工具错误以 `result.isError === true` + HTTP 200 返回。**调用方必须检查 `isError`**，
> 不能只看"响应里有没有 result"就当成成功。

### 4.5 Agent 解析契约（给接入方的速查）

| 想判断 | 看哪个字段 |
|---|---|
| 有没有解 | `resultType` |
| 解可不可信 | `certified` + 每解 `tier` |
| 用哪个解 | `recommended` |
| 是否可能漏解 | `truncated` |
| 出错没 | `isError` + `error.type` |
| 本次是否计费 | `diagnostics.inputError` 为空且返回成功结果才计费 |

## 五、示例（覆盖 6 类结果）

| 标题 | 方程 | 预期 |
|---|---|---|
| 最少 1 变量 | `x^2 = 4` | 2 解 |
| 最多 6 变量 | 6 元三对角线性方程组 | 唯一解 |
| 空集无解 | `x+y=3` 与 `x+y=5` | 空集（**已证明**无解） |
| 有限解·全部 | `x²+y²=4`,`xy=1` | 4 解全认证 |
| 有限解·部分 | `sin(20x)=0.5`,`sin(20y)=0.5`（域 `[-30,30]`） | 多解 + `truncated` |
| 无限解·推荐 | `x+y=3` | 无限集，推荐 `(1.5,1.5)` |

## 六、自托管（远程 HTTP 形态）

```bash
PORT=3000 node http-mcp-server.js
```

零依赖，仅用 Node 内置模块。与本地 stdio 形态共享 `solver-core.js` 求解核心，结果同源一致。

**默认是安全的**：计费默认关闭、管理端点未配置令牌时整体返回 503、管理端点默认只接受本机回环。

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `PORT` | 3000 | 监听端口（注意变量名是 `PORT`，不是 `LS_PORT`） |
| `LS_METERING` | `off` | 计费开关。**自托管默认关闭** ⇒ clone 出去自己跑全免费，不会被我们收钱 |
| `LS_PRICE_CENTS` | `1` | 单价（分/次），仅在计费开启时生效 |
| `LS_FREE_LOOPBACK` | `1` | 本机回环免单 |
| `LS_RATE_MAX` | `120` | 每 IP 每分钟请求上限（超出 429） |
| `LS_ORDER_RATE_MAX` | `10` | 每 IP 每小时下单上限 |
| `LS_ADMIN_TOKEN` | 未设置 | 管理端点令牌（请求头 `X-Admin-Token`）；**未设置 ⇒ `/admin/*` 一律 503**（fail-closed，不存在"无凭证即可加钱"的口子） |
| `LS_ADMIN_LOOPBACK_ONLY` | `1` | 管理端点只接受本机回环（运维走 SSH 隧道，令牌绝不经公网） |
| `LS_REQUIRE_TLS` | `off` | 置 `on` 后，携带凭证的明文调用将被拒（认 `X-Forwarded-Proto: https`） |
| `LS_CREDITS_PATH` | `credits.json` | 账本路径 |
| `LS_PAY_TO` / `LS_PAY_PAGE` / `LS_PAY_CHANNEL` | 未设置 | 收款去向 / 付款页地址 / 收款渠道；**未配置时订单会明确标注「不可付款」**，绝不给死链 |

**账本与隐私**：账本 `credits.json`（只存订单号 + 凭证的 SHA-256 + 余额/次数 + 时间戳 + 来源 IP）
与只增审计流水 `credits.json.ledger.jsonl`。**凭证与原始方程都不落盘明文**。
收款账号有防替换护栏：`LS_PAY_TO` 被改成别的账号会 fail-closed 拒绝生成付款意图（防收款账号被换）。

**反向代理**：对外提供时建议在 nginx 上代 `/mcp`、`/health`、`/pricing`、`/credit`、`/pay/order`，
并加上 CSP、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、请求体上限与限速。
`/mcp` 反代需带 `X-Forwarded-For`（判回环免单依赖它，缺失会把外部请求误判为本机）。

## 七、常见问题

**Q：会算错吗？**
它不会"编"答案：找到的每个解都经区间认证，可回代验证；所以"给出的解"是保真的。
但**不承诺对一切输入都能找全所有解** —— 预算内未能证明穷尽时会明说 `truncated`。
参见 [01 · 产品作用](01-产品作用.md#七对外口径红线不可越)。

**Q：为什么同一道题有时找不到解？**
常见原因是搜索域不合适（默认 ±1e6）。对 `exp`/三角/高频函数请显式给 `domain`，例如 `{"x": [-30, 30]}`。

**Q：`truncated: true` 是不是说明结果不能用？**
不是。它只表示"没能在预算内**证明**已穷尽"。绝大多数情况下真解已经全部找到；若确实缺解，收窄 `domain` 或提高 `budget` 重试。

**Q：支持哪些函数？**
`+ - * / ^`、`sqrt`、`log`、`sin`、`cos`、`tan`、`exp`、`abs`。不含双曲/反三角函数（有意不实现）。

**Q：精度能调吗？**
不能，固定 6 位小数（产品规格）。残差容差有三档：Balanced 1e-6（默认）/ Precise 1e-9 / Fast 1e-3。

**Q：方程内容会不会被上传？**
网页版完全在浏览器内计算，方程不出设备。本地版离线运行。托管端点仅记录元数据（时间/IP/工具/耗时/结果类型），**不记录方程内容**。详见 [privacy.html](../privacy.html)。

**Q：要不要注册账号？**
不需要。托管端点**凭证即身份**（不设用户名、密码、邮箱、手机号）；自托管完全无账号概念。

**Q：托管端点的凭证怎么传？**
请求头 `Authorization: Bearer <key>` 或 `x-api-key`。**不支持把凭证放在 URL 查询串里**（查询串会被反向代理写进访问日志，等于凭证泄露）。

**Q：我自己部署，会不会被你们收费？**
不会。计费默认关闭（`LS_METERING=off`），只有我们自己运维的托管端点才启用按次计费。
