## 一、签署流程

| 步骤 | 动作 | 需要的材料 |

| 1 | 双方确认场景、部署方式、档位与用量 | 使用场景说明、部署方式（托管 / 私有化）、用量预估 |
| 2 | 出报价与授权范围，双方确认 | 报价单（按需提供） |
| 3 | 填写本合同（甲方信息由我方补全主体资料） | 乙方营业执照信息、联系人 |
| 4 | 电子签署 | 腾讯电子签（或双方认可的电子签平台）；亦可纸质双签 |
| 5 | 对公转账付款、开具发票 | 付款凭证 |
| 6 | 交付（密钥/部署包/支持入口）与建联 | 技术联系人 |

**签署方式**：推荐电子签（一式两份、电子签具同等效力）。合同签署地为广州市花都区。

#### 第五条　认证含义、责任与免责（**核心条款，务必保留**）

5.1 **认证含义**：本软件输出的"已认证（`certified`）"指——**在给定数学模型与计算预算内，该解经区间验证、结果可复现**。
**不表示"结果绝对正确"或"100% 无遗漏"。** 在预算内未能穷尽求解的情形，软件会标注 `truncated` / 未认证，
而非伪装通过（fail-closed 设计）。

5.2 **不保证条款**：甲方**不保证**本软件在所有输入下均产出认证解，亦**不保证**计算结果在任何外部用途下绝对无误。
乙方应将认证结果作为信任参考，关键决策须结合自身校验。

5.3 **责任上限**：因本软件授权使用产生的甲方累计赔偿责任，以乙方**已支付的当年授权费**为上限；
甲方不对乙方的间接损失、利润损失、数据损失或第三方索赔承担责任。

5.4 **合规边界**：本软件定位为"**软件授权 / 技术服务**"的计算工具，
**不构成**金融投资、医疗诊断、法律或任何专业领域的认证结论；

## 三、关键条款为什么这样写（给乙方看的说明）

| 条款 | 设计理由 |
|---|---|
| 5.1 认证含义 | **不夸大是这份合同能被长期履约的前提**。"认证"若被理解为"绝对正确"，任何反例都会变成纠纷；写明它的严格含义，双方风险都可控 |
| 5.2 不保证条款 | 与产品对外口径完全一致（见 [01 · 产品作用](01-产品作用.md#七对外口径红线不可越））。产品自己在 `truncated` 上就不撒谎，合同也一致 |
| 5.3 责任上限 = 当年授权费 | 软件授权类合同的通行做法；让"能赔得起"与"卖得起"同时成立 |
| 5.4 合规边界 | 避免本软件被当作金融/医疗/法律结论的依据（这既是对使用者的保护，也避免触及专业领域监管） |
| 3.3 不叠加按次 | 避免同一能力被重复计费；年授权客户的使用不受线上零售通道影响 |
| 7.2 数据条款 | 与 [privacy.html](../privacy.html) 的公示一致：**只存元数据与哈希，不存方程与个人信息** |
| 8.3 终止后删除副本 | 授权是年度的，不是永久买断（旗舰版源码交付按附录单独约定） |

## 四、附件要点（节选）

### 《技术交付附录》（旗舰版适用）

- 交付范围：约定版本的源码 / 构建产物、部署说明、接口文档（[02 · 使用指南](02-使用指南.md)、[04 · 技术参考](04-技术参考.md)）。
- 白标约定：允许/不允许的对外呈现方式；不得暗示与甲方的除授权外的其他关系。
- 版本与更新：交付版本的升级方式、是否含后续版本（默认仅含交付时点版本 + 约定期限内的缺陷修复）。

### 《SLA 细则》要点

- 可用性统计口径（按月/按年、剔除计划维护窗口）、故障分级（P1/P2/P3）、响应与处置时限。
- 例外：乙方自有网络、乙方私有化环境的运维问题不在托管端点 SLA 范围内。
- 补偿方式：按档位约定（通常以服务期顺延为主）。
