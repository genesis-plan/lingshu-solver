# 01 · 产品作用

> 本文回答一件事：**灵数求解器有什么用、对谁有用、边界在哪。**
> 所有表述以实际实现为准，不含规划中或未实现的能力。

---

## 一、一句话

**给"不能算错"的场景提供一个确定性、可验证、不幻觉的数学求解内核。**

同样的题，永远得到同样的答案；每个解都附带一张可独立校验的"已认证"标记。
大模型会一本正经地算错数学，而它是算法——不猜，只算，而且算完能验。

---

## 二、它解决什么真问题

| 痛点 | 现有做法的坑 | 灵数的差异 |
|---|---|---|
| 大模型做数学会**幻觉** | LLM 是概率生成，数字可能编造，且同题不同答、不可复现 | 确定性算法，同输入同输出，**可复现、可审计** |
| 算出来的结果**没有凭证** | 拿到一个数，无法证明"它真的满足方程" | 每个解经 **Krawczyk 区间认证**，误差半径明确，可回代验证 |
| 数值工具的**信任不可分级** | 结果要么"信"，要么"不信"，没有中间态 | 结果分三态（无解/有限解/无限解）+ 认证层级（`proven`/`candidate`）+ 穷尽标记（`truncated`） |
| 复杂/病态系统**假装成功** | 无法判定时也给个看似正常的答案 | 判不出就**明说**（`truncated`、未认证、诊断信息），fail-closed，不伪装通过 |
| 数据**必须留在本地** | 云端计算意味着方程外发 | 网页版零数据上行；本地版完全离线；托管端点不落盘方程内容 |

---

## 三、给谁用

| 用户 | 得到什么 |
|---|---|
| **个人 / 学生 / 教师 / 会计** | 一个"不胡说的方程组计算器"：非线性、带约束都能解，网页打开即用，答案每次一致、可回代验算 |
| **AI Agent 开发者** | 给 Agent 一个**确定性数学后端**：约束求解不再依赖模型临场发挥，结果可缓存、可复现、可验证 |
| **多 Agent / 分布式系统** | 一份**可被第三方独立校验**的中间计算凭证（"这个数确实算对了"），而不是互相信任彼此的算术 |
| **企业 / 私有化场景** | 数据不出域、可自托管、已验证解数学保真，适合嵌入内部系统、风控流水线、合规计算 |
| **审计 / 合规留证场景** | 认证结果与诊断字段可作为结构化凭据，随业务日志一起入档 |

---

## 四、它能做什么

- **求解实数方程组**：1–6 个变量；方程数 ≥ 变量数，服务端上限 64 条。
- **方程类型**：代数方程（多项式、有理式、根式）与常见超越函数（`sin/cos/tan/log/exp/sqrt/abs`）；
  支持 `x^2 + y^2 = 25` 这类等式，也支持 in-text 域约束 `x ∈ [-30,30]`。
- **不需要初值**：采用区间算术保守收缩 + 全局分支定界，不必人工给起点。
- **多解**：尽力穷尽全部实数解；无限解集（如 `x+y=3`）给出距原点最近的推荐解并标 `infinite`。
- **严格证明无解**：某些结构（矛盾方程、区间包络不含 0、结构恒正）可**证明**无实数解，而不是"没找到"。
- **三种形态同一内核**：网页版 / 本地 MCP（stdio）/ 远程 MCP（HTTP）结果同源一致。

---

## 五、它不做什么（诚实边界）

| 不做 | 说明 |
|---|---|
| 符号推导 / 闭式证明 | 不是 CAS，不输出解析解与推导过程 |
| 微分方程（ODE/PDE）初值问题 | 不支持 |
| 整数 / 自然数强制约束 | 按实数域求解，不保证返回整数；会带结构化警告 `integer-unenforced`，不静默忽略 |
| "必不等于"约束 | 暂不支持 |
| 双曲 / 反三角函数 | `sinh/cosh/tanh/asin/acos/atan` 未纳入（有意不实现，见 [03 · 设计思想](03-设计思想.md)） |
| 高精度全域科学计算 | 固定 6 位小数有限网格，定位是轻量数值工具，非科学计算级全域精度 |
| 保证 100% 穷尽 | 一般情形下"保证找到全部解"在数学上不可判定；预算内未穷尽时诚实标 `truncated` |

**规模与范围**：变量 ≤ 6；默认搜索域 ±1e6；输出固定 6 位小数；单次方程文本 ≤ 100KB。

---

## 六、解的可信度怎么读（一表看懂）

| 你想知道 | 看这个字段 |
|---|---|
| 有没有解 | `resultType`：`empty`（**已证明**无实数解）/ `finite`（有限解）/ `infinite`（无限解集，给推荐解） |
| 解可不可信 | `certified`（是否全部 `proven`）与每个解的 `tier`：`proven`（Krawczyk 已认证）/ `candidate`（候选）/ `structural`（结构推导） |
| 该用哪个解 | `recommended`（距原点最近 / 范数最小） |
| 是否可能漏解 | `truncated`（`true` = 预算内未证明穷尽，建议收窄 `domain` 或提高预算后重试） |
| 出错没有 | MCP 响应的 `isError` 与 `error.type` |

---

## 七、对外口径（红线，不可越）

**可以说**：确定性、可复现、可验证、无幻觉、已验证解数学保真、全局穷尽尽力而为、
Krawczyk 区间认证、离线、零依赖、零数据（对应形态）、≤6 变量、固定 6 位小数、未穷尽时诚实标记。

**不可以说**：
- ❌「保证不漏解」「100% 不会错」「绝对精确」「零风险」
- ❌「金融级认证」「医疗合规认证」等专业领域认证暗示（本产品是数学计算工具，不构成任何专业结论）
- ❌ 承诺未实现的能力（如整数强制、ODE、双曲函数）

**理由**：这是一个把"诚实"当作核心卖点的产品。夸大会同时毁掉技术与商业两方面信誉——
买方买的正是"它不乱说"这件事。

---

## 八、一句话价值

> **它不是又一个计算器，而是一个可验证的数学信任锚：**
> 算得出的部分盖章（认证），算不出的部分明说（诚实降级）。
