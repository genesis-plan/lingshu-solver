# suan60：线性系统精确栈 — presolve 裁剪 + Markowitz 稀疏序 + 零空间参数化

> 落地日期：2026-10-03
> 定位：**3～6 元全线性系统的专用快路径**。不是通用求解器的替代，而是在调度上**前置接管**线性系统 —— 因为线性系统有精确的数学结构可用，而通用路径（采样 + 牛顿）只能碰运气。
> 硬上限：**只接管 3 ≤ n ≤ 6**。`n > 6` 一律 fail-closed 交回旧路径，零行为变更。

---

## 一、为什么需要它（实测缺口）

产品原有线性方程组路径是 **suan17 朴素高斯 + 多起点牛顿**：

- 无精确秩判定（判无解靠浮点阈值猜）
- 无 presolve 裁剪（稀疏系统也照做满消元）
- 欠定系统的族解靠**随机撒点碰运气**（定义域四分点起步，牛顿迭代收敛到哪算哪）

实测缺口（2026-10-03，6 变量稠密整数系统）：纯精确消元 **79 ms/题**，SymPy 1.14 `linsolve` **3.58 ms/题** —— 我们比被超越对象慢 22 倍。

## 二、数学链条

```
A x = b,  A ∈ Q^{m×n},  n ≤ 6
  │
  ├─【通道 1 · 快】浮点 + Markowitz 稀疏序选主元  ⇒  O(n³) 次 IEEE754 双精度
  │      候选解 x̂
  │
  ├─【通道 2 · 严】把 x̂【精确代入】原方程组          ⇒  O(n²) 次 BigInt 有理运算
  │      残差严格为 0 ⇒ 采纳（浮点解也带严格证明）
  │      残差 ≠ 0 ⇒ 降级到通道 3
  │
  └─【通道 3 · 兜底】Bareiss 分数自由消元（精确有理）  ⇒  强多项式
         零就是零 ⇒ 精确秩判定 / 严格无解证明
```

**为什么通道 2 成立（这是速度的关键）**：唯一解时 `A⁻¹b` 只有**一列**，
验证 `Ax̂ = b` 只需 `O(n²)`，无需重算消元。79 ms → **0.075 ms**（约 1000×）。

## 三、presolve 裁剪族（论文依据）

依据 Gondzio 1997 *IJOC* 9(1):73-91 与 Andersen & Andersen 1995 *Math. Prog.* 71:221-245
（Gurobi presolve 分类见 Achterberg 等 2018/2020 *IJOC* 32(2):473-506）。

| 规则 | 判定 | 处置 | 状态 |
|---|---|---|---|
| R1 空行 | 整行系数为 0 | `0 = b(≠0)` ⇒ **严格无解**；`0 = 0` ⇒ 删行 | ✅ 已实现 |
| R2 空列 | 整列为 0 | 该变量恒 0 ⇒ 固定为 0，删列 | ✅ 已实现 |
| R3 单例行 | 行内仅 1 个非零 | **精确固定**该变量、删行、在其余行做等价行变换消去该列 | ✅ 已实现 |
| R5 重复行 | 按**成比例**判定 | 系数成比例且 rhs 相容 ⇒ 删冗余行 | ✅ 已实现 |
| R7 严格对角占优 | Levy–Desplanques 定理 | 非奇异 ⇒ 唯一解提前定论，跳过消元 | ✅ 已实现 |
| R4 单例列 | — | **不实现**（见下方踩坑） | ❌ 主动禁用 |
| R6 重复列 | — | **不实现**（见下方踩坑） | ❌ 主动禁用 |

Gondzio 1997 的实测：根节点关 presolve 慢 **10.8×**，其余节点关 1.3×。

### 踩过的坑（保留记录，防止重犯）

- **单例列规则在数学上不成立**。反例：`x+y+z=6, x−y=4`（三列全是单例列）被误判为唯一解。
  列稀疏只说明「该行更新代价低」，与「变量可解性」无关 —— **只有单例行才能定值**。
  该规则的稀疏性价值已交给 Markowitz。
- **重复列不能删**。两列成比例时删一列 ⇒ `x1, x2` 只由其一决定 ⇒ **丢失自由度**。
- **浮点 presolve 的「重复行」不能只比零/非零结构**。稠密 6×6 每行零/非零结构完全相同，
  6 行会被删成 4 行 ⇒ 变成伪欠定。必须**按成比例判定**（整行除以首个非零元 + rhs 除以同一元素）。
  已加回归锁。

## 四、Markowitz 稀疏序 + Zlatev 稳定因子

依据 Markowitz 1967、Zlatev 1996。

- 代价函数 `M_ij = (r_i − 1)(c_j − 1)`（消元产生的 fill-in 上界）
- 稳定因子约束 `|a_ij| ≥ u · max_k |a_kj|`（u 默认 0.1）
- 搜索范围限制在 **best rows**（非零最少的 3 行）

**理论边界（诚实标注）**：最小 fill-in 是 **NP 完全**的
（Rose/Tarjan/Lueker 1976、Yannakakis 1981）⇒ 这里只能是启发式，不宣称最优。

## 五、秩亏系统：零空间参数化仿射采样

### 5.1 问题

2026-10-03 接入首版后，产品回归从 **50/50 掉到 46/50**。唯一失败用例
`T_Wikibooks_P2_4var`（4 方程 4 变量但 `rank = 3`）。

A/B 实测（同机同题）：

| 版本 | 路径 | 解数 | known 命中 | ms/次 |
|---|---|---|---|---|
| 基线（无 suan60） | 多起点牛顿 | 5 | **5/5** | 458.7 |
| 首版 suan60 | 精确秩判定 | 1 | 1/5 | 322.5 |

原因：`family` 分支只给一组特解就 `state.done = true`，**抢断**了后续族解枚举。

### 5.2 解法：不是「交回旧路径」，而是把解流形解析采出来

秩亏相容线性系统的解集**不是离散点集，而是仿射子空间**：

```
解集 = { x_p + Σ_j t_j · N_j }      x_p = 特解, N = 零空间基
```

- 零空间基 `N` 由**精确有理 RREF** 求出：自由列 `f` 配一个向量，
  `f` 位为 1、主元位为 `−R[row][f]`。这组向量线性无关且张成全部零空间。
  精确有理 ⇒ 零就是零，不存在 EPS 把「真零」误判成「很小」而造出伪自由列。
- 沿单条基走 `x(t) = x_p + t·N`。box 约束对 `t` 是**线性不等式**，
  逐坐标解析求交得可行区间 `[tMin, tMax]` —— 这是**解析裁剪**，不是撒网。

### 5.3 采样格（唯一的启发式成分，诚实标注）

沿 `t` 取**半整数格** `t ∈ 0.5·ℤ ∩ [tMin, tMax]`。

- ⚠ 2026-10-05 更新：原理由是「输出契约是 6 位有限网格」—— 该网格已移除。**现在的理由更强**：对整系数系统，零空间基分量是小分母有理数（如 1/3），**任何有限小数网格都无法精确表示**（实测 23/30 被压到 0.766667 后残差 2.3e-6 ⇒ 被残差闸门误杀）⇒ 网格化对有理数解是**原理性不可行**，不只是精度不够
  （分母通常 ≤ 2），取 0.5 的倍数作参数恰好把 `x_p` 与 `N` 的分母对齐，
  得到半整数格上的代表解 —— 正是人手算这类系统时会写下的解。
- 实测依据：该回归用例的 5 个参考解，其流形参数恰为 `t = 0, 1, 2, 2.5, 3`，
  全部落在半整数格上。
- 区间过宽（> 128 个半格）时退化为均匀细分 256 点，防解爆炸。

### 5.4 完备性边界（不夸大）

解流形是**连续**的，半整数格只是**代表元采样**，不是「穷尽所有解」。

真正的完备性来自：给定任意 `t`，`x_p + t·N` 可**精确构造**并通过精确代入验证。
若区间宽 < 0.5 导致无半格点，则只给特解 —— 此时旧路径的随机撒点同样拿不到更多。

## 九、踩过的坑（全部保留记录）

| 坑 | 现象 | 根因 | 修法 |
|---|---|---|---|
| `Cannot mix BigInt and other types` | `_s60gcd` 崩溃 | 误把已有理数对象当 `[p,q]` 元组传入 | 直接引用对象 `M[n-1][n-1]` |
| 单例列规则 | `x+y+z=6, x−y=4` 误判唯一解 | 列稀疏 ≠ 变量可解 | 彻底删除 R4 |
| 重复列删除 | 解集被缩小 | 丢自由度 | 不实现 |
| 浮点重复行只比结构 | 稠密 6×6 被删成 4 行 | 零/非零结构相同就误判 | 改为按成比例判定 |
| Householder 给错解 | `[[1,1],[1,2],[1,3]]` 给 `(1.488, 0.423)` | ① `v` 覆盖 M 第 k 列 ② 循环漏了 `k = n−1` 那一轮 | ① v 存独立数组 ② 循环改 `k < n` |
| `process.perf_counter is not a function` | benchmark 崩溃 | Node 无此 API | `import { performance } from 'perf_hooks'` |
| benchmark ms 错 1000 倍 | 报 37–175 ms/次 | `performance.now()` 已返回毫秒又乘 1000 | `rec.ms = dt` |
| `rank` 语义错 | 3×3 满秩报 `rank: 2` | 报的是裁剪**后**剩余系统的秩 | `rank = res.rank + nFixed`（另加 `rankAfterPresolve` 供审计） |
| 性能严重劣势 | 37–175 ms，慢 SymPy 22× | 全走 BigInt 精确消元 | 双通道架构（浮点出候选 + 精确代入验证） |
| `diagDominant` 不命中 | 循环占优阵测试失败 | 只在精确 presolve 里 | 新增 `_s60diagDominantFloat` |
| **family 抢断** | 回归 50/50 → 46/50 | 特解即 `done`，掐断族解枚举 | 零空间参数化仿射采样 |
| **box 取值来源错** | 采样仍只得 1 解 | 域在 `state.D0`，但只读了 `state.domainConstraints` | 两处都读并取交集 |

## 十一、诚实声明（对外口径）

- **不是**「保证不漏解」。秩亏系统的族解采样是**代表元采样**（半整数格），不是穷尽。
- Markowitz 选主元是**启发式**，最小 fill-in 是 NP 完全的。
- 速度优势仅在 **3 ≤ n ≤ 6 且全线性**这一段成立，且基准为单题同机实测（WARMUP=3、REPEAT=20）。
- `n > 6` 不接管 —— 行为与接入前完全一致。
