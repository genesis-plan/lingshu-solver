## 一、数学框架

### 1.1 区间算术与仿射算术（可靠性基础）

- 所有计算基于**区间算术** `[a, b]` 与**一阶仿射算术**：变量取值永远是"一个盒子"而非一个点。
- 区间是运算结果的**严格包络**（舍入方向受控）：**区间不含 0 ⇒ 严格证明该盒子内无解**。
- 由此得到的 sound 性质是整个产品"能证无解、能盖章"的地基，浮点误差不会破坏它。

### 1.2 六个主力收缩算子

盒子在搜索中不断被收缩：保留必然含解的部分、剔除必然无解的部分。

| 算子 | 方法 | 作用 |
|---|---|---|
| `suan27` | HC4-Revise | 前向严格空集证明 + 反向 hull 一致性收缩 |
| `suan28` | 约束反演系统化 | 广义项一致性、fixpoint 循环、扩展逆函数（含幂逆、log10） |
| `suan31` | Box-Consistency (BC3) | 逐变量盒一致性 |
| `suan32` | 成对 2B / 3B-Consistency | 相邻约束对的一致性 |
| `suan33` | Hansen-Sengupta | 区间 Gauss-Seidel，利用雅可比 |
| `suan34` | LP Narrowing | 精确线性松弛 + 单纯形，可严格证明无解 |

### 1.3 解的认证：Krawczyk 不动点构造

- 输出解列表中的每个点都经 **Krawczyk 算子**认证：证明该邻域内**存在唯一解**，并给出误差半径。
- 无法认证的候选点降级为 `candidate`（候选）并明确标注，与 `proven`（已证明）严格区分。

### 1.4 全局搜索：区间分支定界

- `suan47` 全局分支定界：递归二分盒子，配合收缩算子剪枝，**尽力穷尽**全部解。
- 预算参数：`BUDGET = 5e5` 盒、`MAXDEPTH = 28`（单维分辨率约 `7e-5`）、`MINW = 1e-4` 提前停。
- **诚实边界**：对极端病态系统（雅可比高度奇异、解簇极度贴近），预算内仍可能遗漏个别解。
  此时结果显式标记 `truncated` / 残余告警，**绝不谎称已穷尽**。
- 对周期/高频单变量方程（如 `sin(100x)=0`），`suan22` 周期感知自适应扫描补全全部根。

### 1.5 已知限制（如实声明）

- 整数约束（`x∈ℤ/ℕ`）**不做强制执行**：按实数域求解，结果带结构化警告 `integer-unenforced`。
- 不等式系统支持可行域判定，结论分级为"有限可行解 / 可行域可能非空"。
- 双曲函数与反三角函数未纳入（有意不实现）。
- 5–6 变量强非线性系统可能算不完，只输出已认证的部分结果与范围。

## 二、结构框架

### 2.1 系统组成

```
┌────────────────────────────────────────────────┐
│              求解核心（唯一真源）                 │
│      index.html → <script id="solver-core">     │
└──────┬───────────────┬───────────────┬─────────┘
       │               │               │
  solver-core.js  mcp-server.js  http-mcp-server.js
   （vm 加载器）    （stdio 版）    （streamable-http 版）
       │               │               │
   npm 包 / 网页     本地 MCP 进程    线上 /mcp 端点
```

### 2.2 部署拓扑与数据行为

| 组件 | 位置 | 数据行为 |
|---|---|---|
| 网页求解器 | 静态托管 + 浏览器 | **零数据上行**：方程在浏览器内计算 |
| MCP HTTP 服务 | 服务器 :3000（nginx 反代 `/mcp`） | 内存求解后随应答返回，**不落盘方程与结果** |
| 调用日志 | 服务器本地 `calls.log` | 仅元数据（时间/IP/工具/耗时/结果类型），**不含方程内容**，轮转 |
| 安全层 | nginx | CSP / `X-Frame-Options: DENY` / `nosniff` / 限速 429 / 请求体上限 413 |

### 2.3 隐私与安全（已落实）

- 无账号、无 Cookie、无埋点、无第三方脚本；不支持文件上传。
- 输入门禁（`_complianceGuard`，网页与 MCP 共用）：拒收自然语言文字 + 100KB 体量上限；
  **数字串（电话/证件号式）不拦截**，按普通数学常量处理。
- 服务端防护：请求体 256KB 上限（413）、每 IP 120 次/分钟（429）、会话 TTL 清理、反馈落盘前脱敏。
- 结果仅请求者本人可见，无公开分享/展示功能。
- 托管端点账本只存：订单号 + 凭证 SHA-256 + 余额/次数 + 时间戳 + 来源 IP；**凭证明文与方程内容一律不落盘**。

## 三、算法流水线（11 层）

```
setup/guard ──▶ prove(轻量矛盾) ──▶ contract(域收缩) ──▶ rewrite/solve(代数闭式)
                                                          │
                                                          ▼
                                              contract(区间/仿射收缩核心)
                                                          │
                                                          ▼
              prove(单调/凸性剪枝) ──▶ analyze(几何拓扑) ──▶ sample(流形)
                                                          │
                                                          ▼
              solve(数值迭代) ──▶ filter(后处理) ──▶ search(分支定界) ──▶ output
```

| 层 | 职责 | 算子 |
|---|---|---|
| 0 · 解析与护栏 | 输入标准化、超限拦截（变量 >6、危险算子） | `suan1`–`suan6` |
| 1 · 轻量矛盾证明 | 区间前向传播、常量矛盾、结构恒正/恒负（`sound=true`） | `suan7`、`suan10`、`suan11` |
| 2 · 自动约束与基础收缩 | 隐含定义域推导（根号内非负、分母非零）、压缩映射 | `suan9`、`suan12` |
| 3 · 代数闭式求解 | 化简 → 消元 → 回代（**强顺序依赖**） | `suan15`–`suan23` |
| 4 · 区间/仿射收缩核心 | 主力收缩栈 | `suan24`–`suan34` |
| 5 · 单调/凸性证明剪枝 | 导数 + 中值定理 + 凸性严格剪枝 | `suan29`、`suan30`、`suan35` |
| 6 · 几何拓扑分析 | 只写性质，不收缩域 | `suan8`、`suan13`、`suan14`、`suan36`、`suan37` |
| 7 · 采样与流形 | 为数值层提供初值 | `suan38`、`suan39` |
| 8 · 数值迭代求解 | 线搜索牛顿、区间牛顿兜底、不等式系统 | `suan40`、`suan41`、`suan48` |
| 9 · 后处理过滤 | 残差过滤、剔伪根、去重合并 | `suan42`–`suan46` |
| 10 · 兜底搜索与输出 | 分支定界（`truncated` 诚实标）、收敛判定与格式化 | `suan47`、`suan49` |

## 五、处理流程（端到端）

```
用户输入（网页文本框 / MCP equations 参数）
   │
   ▼
① 预处理 fuzzyFix（核心层，网页与 MCP 两路径共用）
   Unicode 归一（− · ≠ 上标 √）→ 换行修复 → 隐式乘法 → log2/log10 识别 → 补 =0
   ▼
② 输入门禁 _complianceGuard：自然语言拒收、100KB 上限
   ▼
③ 解析：tokenize → parse → AST；自动识别变量（含希腊字母 θ/α 归一）
   ▼
④ D0 初始化：用户指定域合并默认域 ±1e6；缺失变量回退默认（不崩溃）
   ▼
⑤ 求解管线 _solveImpl（阶段 1 前置拦截 → … → 阶段 7 分支定界/输出）
   屏幕剪枝 → 代数消元 → 区间收缩（六算子迭代）→ Krawczyk 认证 → 全局分支定界
   ▼
⑥ 收尾 _finish：反例剔伪根 → 良定义校验 → 结果分类与诚实标注
   ▼
⑦ 输出（网页渲染 / MCP JSON 应答）：解列表 + certified / truncated 等标志
```

网页路径与 MCP 路径仅在 ①⑦ 的入口出口不同，②–⑥ 完全一致。

**防失控三道保险**：① 共享根时钟（整流子树硬超时）；② 共享预算池（分支子调用不重置盒预算）；
③ 体量护栏（方程 ≤64、变量 ≤6、文本 ≤100KB、请求体 ≤256KB）。

## 六、规格硬约束（速查）

| 项 | 值 | 性质 |
|---|---|---|
| 变量数 | 1–6 | 超出直接拒收 |
| 方程数 | ≥ 变量数，服务端 ≤ 64 条 | 超出拒收 |
| 方程文本总长 | ≤ 100KB（请求体 ≤ 256KB） | 超出拒收 |
| 默认搜索域 | ±1e6 | 可用 `x ∈ [a,b]` 或 `domain` 覆盖 |
| 输出精度 | 固定 6 位小数 | 不随输入变化 |
| 残差容差 | 1e-6 Balanced / 1e-9 Precise / 1e-3 Fast | 三档 |
| 预算 | `BUDGET=5e5` 盒、`MAXDEPTH=28`、`MINW=1e-4` | 可加大重试 |
| 已验证解 | Krawczyk 保真（误差 ≤ 认证半径） | 数学保证 |
| 多解穷尽 | 全局分支定界，尽力而为 | 未穷尽标 `truncated`，**不承诺不漏解** |
| 第三方依赖 | 0 | 核心与服务端 |
| 数据外发 | 0（网页）／不落盘内容（MCP） | 对应形态 |
