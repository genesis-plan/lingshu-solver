## 二、版本号语义

采用 `主版本.次版本.修订号`（`MAJOR.MINOR.PATCH`）：

| 变更类型 | 升位 | 例子 |
|---|---|---|
| **求解结果发生变化**（算法、剪枝、认证行为、精度语义） | **次版本 +1** | 修一个会导致"该有解却报无解"的缺陷 |
| **接口不兼容变更**（删除字段、改变参数语义、改变错误语义） | **主版本 +1** | 移除某个入参、改变 `resultType` 取值含义 |
| 仅展示层 / 文档 / 分发 / 安全加固 / 性能，数值行为不变 | **修订号 +1** | 页脚备案号、`/health` 字段、npm 打包内容 |
| 新增可选字段或可选参数（向后兼容） | 次版本或修订号 +1，并在本文记录 | 新增 `diagnostics` 子字段 |

**判据一句话**：*同一个输入在升级前后是否可能得到不同的数值结果？*
会 ⇒ 至少升次版本，并在发布说明里写明；不会 ⇒ 修订号即可。

## 四、兼容性承诺

我们承诺（在使用者视角）：

1. **响应字段只增不删**：`solve` 返回的既有字段名与语义在同一主版本内不变；新增信息一律加在子块（如 `internals`、`diagnostics`）里。
2. **数值行为变更必须可预期**：会改变求解结果或认证结论的改动**只在次版本发布**，并在发布说明中写明"哪种输入会变、往哪个方向变"。
3. **诚实标记不倒退**：`certified` / `truncated` / `tier` / 诊断字段只可能变得更准确、更细，不会为了"看起来更好"而放宽。
4. **弃用提前通知**：任何字段或参数的移除，至少**提前一个次版本**在文档与发布说明中标注弃用。
5. **复现性保证**：同一版本 + 同一输入 ⇒ 同一输出。因此**升级前请记录 `diagnostics.solverVersion`**，
   需要长期复现的场景请固定版本（npm 依赖锁版本 / 私有化部署固定交付包）。

**不承诺**：跨次版本数值结果逐位一致（修缺陷本身就可能改变结果——这正是修它的目的）。

## 五、发布流程（维护者清单）

发布一个版本 = 让**四处的版本信息一致**，缺一处就会出现"功能是新的、号是旧的"。

### 5.1 版本一致性清单

| # | 位置 | 核对方式 |
|---|---|---|
| 1 | 包与登记清单：`package.json`、`glama.json`、`server.json`、`registry-server.json` | 逐一检查 `version` 字段（`manifest.json` 是网页版 PWA 清单，不含版本） |
| 2 | **运行时自报常量**：`http-mcp-server.js` 的 `SERVER_VERSION` | 这两处**不会**被清单升级自动同步，必须手改 |
| 3 | **网页版常量**：`index.html` 的 `SOLVER_VERSION` | 同上 |
| 4 | **线上实测** | `curl -s https://<域名>/health`（`version` + `solverVersion`）、`curl -sk https://<域名>/ \| grep SOLVER_VERSION` |
| 5 | **两个 npm 渠道**：npmjs（`lingshu-solver`）与 GitHub Packages（`@genesis-plan/lingshu-solver`） | `curl -s https://registry.npmjs.org/lingshu-solver/<ver>`、`GET https://api.github.com/user/packages/npm/lingshu-solver/versions`（两个渠道都由工作流/发布脚本驱动，人工不要单独改其中一个） |

> ⚠️ **nginx 的 `root` 指向哪，首页就由哪份文件决定**。线上曾同时存在两份 `index.html`
> （网站目录一份、服务目录一份），只改一份会导致"`/health` 变了、首页没变"。
> 改对外可见常量前，先确认**真正被服务的那份文件**，并把所有副本一起覆盖、逐份校验哈希。

### 5.2 发布步骤

1. **改代码并本地验证**：跑常驻考卷 + 相关专项（见 [04 · 技术参考](04-技术参考.md#八测试体系)），全绿再动。
2. **同步 §5.1 的第 1–3 项**（清单 + 两处运行时常量）。
3. **部署并实测第 4 项**（`/health`、首页版本号、一次真实调用）。
4. **更新版本历史**（本文第六节）与 `README` 首页版本相关信息。
5. **打 tag + GitHub Release**：tag 名与 `package.json` 版本一致（`vX.Y.Z`）。
6. **`npm publish`**（主渠道 npmjs），随后用**新版本号端点**复查：
   `curl https://registry.npmjs.org/lingshu-solver/<version>`。
7. **GitHub Packages 渠道**由 `.github/workflows/publish-package.yml` 自动跟随：
   在 GitHub 上**发布 Release** 时触发（也可手动 `workflow_dispatch`），
   它会把包名换成作用域形式 `@genesis-plan/lingshu-solver` 后发布到 `npm.pkg.github.com`，
   并在发布前先跑常驻考卷与 MCP 冒烟。**幂等**：该版本已存在则跳过（不会让 CI 变红）。
8. **通知**：年授权客户中受影响的（数值行为变更 / 接口变更）单独知会。

> ⚠️ **GitHub Packages 的两个已知约束**（踩过的坑）：
> ① 新包**默认 private**，而 REST API **没有**改可见性的端点 —— 只能到
> `https://github.com/users/genesis-plan/packages/npm/package/lingshu-solver/settings` 的
> **Danger Zone → Change visibility** 手动改 public（**且改 public 后不可逆**）；
> ② GitHub Packages 的 npm 即使公开，**安装也需要 GitHub 令牌** ——
> 所以它定位是"GitHub 原生/企业内网"补充渠道，**公开分发的主渠道仍是 npmjs**（`npx -y lingshu-solver` 零门槛）。
> ③ **查"某版本是否已发布"只能用整包元数据端点**：`GET https://npm.pkg.github.com/@genesis-plan%2flingshu-solver`
> （带 `Accept: application/json`）后看 `versions` 里有没有该版本号。带上版本号的子路径
> `…/@genesis-plan%2flingshu-solver/1.0.10` 在 GitHub Packages 上**恒返回 405**，
> 拿它做幂等预检会永远判"不存在"（实测踩过一次）；工作流里同时保留 **409 兜底**。
> ④ **包出现在仓库侧栏（Packages 区）需要"连接仓库"，且只能网页操作**：包发布后仓库侧栏仍可能写着
> "No packages published" —— 因为 `package.json` 里的 `repository` 字段只让包页面显示"仓库来源"，
> **不等于真的关联**。要用 GraphQL 判定：`repository(owner,name){packages{totalCount}}`（为 0 即未关联）。
> 关联方式：`https://github.com/users/genesis-plan/packages/npm/package/lingshu-solver`
> → **Connect repository** → 选 `lingshu-solver` → 确认。**REST 与 GraphQL 都没有这个端点**，必须点一次；
> 关联后包默认继承该仓库（公开仓库）的权限，工作流也自动获得包的访问权。

> 📌 **npm 的可见性延迟**：`npm publish` 打印成功且退出码为 0 后，registry 可能需要约 **30 分钟**才对外可见。
> 期间单版本端点 404、`latest` 仍是旧版、tarball 404、重复 publish 报
> `409 Cannot publish over previously staged version` —— **这些都是"正在处理"的中间态，不是失败**。
> **不要据此改号**（改号会让仓库与 registry 永久错位）。判失败的门槛是"等足够久后复查单版本端点"，
> 终局证据是 **shasum 与发布票根一致**。

### 5.3 回滚

- 线上：保留改动前的文件备份（`*.bak-<时间戳>`），回滚 = 覆盖 + 重启服务。
- **注意**：若某次改动删除了模块，回滚到“删除前”的旧备份时需同时确认被删模块是否仍在（否则会缺文件）。
- npm：已发布版本不可删除重发（不可覆盖已发布版本号），回滚 = 发布新的修订号并说明。
